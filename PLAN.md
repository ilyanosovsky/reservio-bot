## [ ] Фаза 2 — Booking engine + инфраструктура разработки (~1 день)

Репо `github.com/ilyanosovsky/reservio-bot`, PR-процесс (charliecreates
ревью, protected main, vitest, CI). `src/reservio/client.ts` +
`src/core/booking-engine.ts` + мультипрофили:

- Клиент API: availability / createBooking / cancelBooking(token) /
  getBooking(token), retry с backoff (429/5xx), таймауты запросов ≤ 5 c.
  Отмена: PATCH `state:"canceled"` (одна L), успех только по state в ответе.
- Профили (`src/core/profiles.ts`): конфиг { контакт, времена, приоритет
  кортов, дни }; engine полностью параметризован профилем.
- Scheduler: ПОЧАСОВАЯ дроп-модель — для каждого целевого часа H дня T+7
  своё окно наблюдения с (H-1):58:30 дня T.
- Engine: функция `bookSlotDrop(profile, target)`:
  - polling слотов с (H-1):58:30 каждые 2 c, окно ≤ 5 мин
  - слот появился → мгновенный POST на приоритетный корт
  - ошибка/занято → fallback на следующий корт из приоритета профиля
  - результат: структурированный отчёт { court, slot, bookingId, token, ms,
    timeline } либо типизированная ошибка (SlotTaken / ApiChanged / Timeout)
- Идемпотентность: перед POST — проверка state, что на эту дату+время+профиль
  брони ещё нет. booking_id + token сохраняются в state.
- Unit-тесты (vitest): расчёт дат T+7 и дроп-окон в Asia/Tbilisi (+04:00,
  границы месяца), построение payload, fallback-логика, идемпотентность,
  «canceled»-споллинг (мокнутый API).

**Критерий приёмки:** тесты зелёные; сценарии успех C3 / C3 занят → C2 /
всё занято / API сломался проходят на моках. Живой прогон СЕГОДНЯ вечером
(30.07): дропы ~19:58:50 (слот 20:00) и ~20:58:50 (слот 21:00) на 06.08 —
вручную, под наблюдением; расхождения с моделью фиксируются в PROTOCOL.md.

## [ ] Фаза 3 — Telegram-бот + state (~1–1.5 дня)

grammY + SQLite (`src/bot/`, `src/core/state.ts`):

- 20:45 — pre-drop сообщение: план брони + кнопки
  `⏭ Пропустить сегодня` / `✅ Бронируем` (default: бронируем).
- 21:0x — результат: успех (корт, слоты, время исполнения) или ошибка.
- Напоминание за 2 часа до игры: «Через 2 часа: Court 3, 20:00–22:00».
- Команды/кнопки: `📅 Мои брони` (из state + sync с API),
  `❌ Отменить сегодняшние` (cancel по сохранённым booking_id, с подтверждением).
- state: таблица bookings (date, court, slot, booking_id, status),
  таблица settings (skip_dates и т.п.).
- Единственный авторизованный chat_id (env `TELEGRAM_CHAT_ID`) — бот
  игнорирует всех остальных.

**Критерий приёмки:** полный суточный цикл прогнан вручную с тестовыми
временами (сдвинутый «дроп» через 5 минут): pre-drop → skip работает,
бронь → уведомление, напоминание T-2ч, отмена работает.

## [ ] Фаза 5 (опционально) — LLM-хвост и расширения

- Свободные запросы из чата: «найди 2 часа подряд в субботу днём» →
  дешёвая модель (Claude Haiku / Gemini Flash) парсит в JSON-intent
  `{date, timeRange, durationHours, courts[]}` → детерминированный поиск
  по availability всех 6 кортов → ответ списком, кнопка «забронировать».
- Поиск парных (смежных) часов: чистая функция по слотам, LLM не нужен.
- Бронь по запросу в произвольное время из чата.
- Self-healing по триггеру: при ошибке ApiChanged — разовый прогон агента
  для исследования нового флоу (НЕ по расписанию).

## Решения, зафиксированные заранее

| Вопрос | Решение |
|---|---|
| Архитектура | Путь A: прямой API, детерминированное ядро, без LLM |
| Дроп-модель | Почасовая rolling T+7: слот часа H появляется ~(H-1):58:50 дня T. Для 20:00+21:00 — два дропа: ~19:58:50 и ~20:58:50 |
| Гонка за слот | Polling с (H-1):58:30, шаг 2 c — цель: бронь за < 5 c от появления |
| Мультипрофили | Профиль = контакт + правила (времена, приоритет кортов, дни); engine параметризован профилем; у девушки свой email/время/корт |
| Процесс | Только PR; ревью charliecreates с явным резолвом комментов; мерджит пользователь при полном зелёном; main protected; vitest; wiki |
| Cron | trigger.dev (proj_fxjnzqesxsicrpeuepzv) |
| Модели разработки | Fable — оркестрация, Opus — сложное, Sonnet — мелочь |
| 2 часа игры | Два booking: 20:00 и 21:00 (слот = 59 мин) |
| Приоритет кортов | Court 3 → Court 2, оба слота на одном корте; если 20:00 взят только на C2 — оба на C2 |
| Częściowy успех | Если взят только один час из двух — бронируем его, в отчёте явно помечаем частичный успех |
| Логин | Guest-бронь с email аккаунта; никакого OAuth/паролей |
| UX пропуска | Pre-drop сообщение 20:45 с кнопкой, а не команда заранее |
| Модели | Core: ноль LLM. Фаза 5: Haiku/Flash-класс, frontier не использовать |
